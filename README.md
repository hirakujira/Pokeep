# Pokéep · Pokémon GO iPhone 自動掃描與清倉助手

繁體中文本機網頁：透過 [iPhone Use](https://github.com/zhongerxin/iPhone-use) 直接掃描寶可夢盒子，以 OpenAI 辨識來源畫面，依團體戰、PvP 與收藏代表整理建議。新增資料只走手機掃描；舊收藏與 v1／v2 備份仍可讀取。

## 啟動

需要 Node.js **24 LTS**（使用內建 SQLite）。

```sh
npm install
npm run data:update
npm run dev
```

開啟 **http://127.0.0.1:3000**，到「設定」頁填入 API key、模型，以及需要時的 OpenAI 相容伺服器網址（完整網址，含 `/v1`）。沒有 key 時無法啟動自動掃描。預設使用 OpenAI API，與 ChatGPT 訂閱額度分開。相容伺服器須支援 Responses API、圖片輸入與結構化 JSON 輸出；即使服務不驗證 key，也須填入它接受的非空值。設定儲存在這台 Mac 的 `.data/`，修改後不必重啟網頁。

正式本機啟動：`npm run build` 後執行 `npm start`。兩種方式都只監聽 `127.0.0.1`；`PORT=3001 npm start` 可切換埠號。啟動指令同時管理網頁與 iPhone 背景服務。關閉網頁不會中斷背景工作，重新開啟可查看進度；不需要保持 Codex 聊天開啟。

## iPhone 掃描

1. 在 Mac 上安裝 iPhone Use，以 USB 連接 iPhone，依其 setup 指引完成信任、開發者模式、Apple 開發團隊簽名及 WDA 啟動。若 WDA 回報 `No Account for Team`，確認 iPhone Use 設定的 Team ID 與 Xcode 目前登入帳號的團隊一致。Pokéep 預設讀取 `/Users/Hiraku/Develop/utils/iPhone-use`；其他位置或 Python 執行檔在網頁「設定」頁修改，然後重新按「檢查連線」。
2. 解鎖手機，在 Pokémon GO 開啟寶可夢盒子。網頁「iPhone 掃描」按「檢查連線」，選擇「目前搜尋結果」或「整個盒子」，再開始掃描。整個盒子會先嘗試清除遊戲搜尋與篩選；無法確認清除時會暫停。
3. 背景服務只在開始時確認寶可夢盒子及所選範圍，之後用直式 iPhone 版型的固定座標逐隻擷取能力、招式／成本與評價畫面，不逐頁呼叫 AI 判斷。截圖時仍用本機 IV 條量測與靜態身分區指紋避免存下不穩定評價或重複翻頁。累積 20 隻完整的三張截圖後，背景解析便與手機截圖同時進行；截圖期間最多使用 2 個解析請求，優先保留手機操作速度，截圖完成後才使用設定的完整並行數（1–8）解析剩餘項目。Mac 上的 Vision OCR 讀取文字，IV 由本機像素量測；AI 只校對 OCR 文字與裁切後的能力頁外觀，不上傳完整截圖或評價條。解析後若暗影／淨化仍未知，可用能力頁與評價頁的外觀裁圖複核；兩張清楚且均顯示普通外觀時，只補上「非暗影」，淨化仍待核對。兩張都明確顯示暗影或淨化效果時才補上對應狀態。解析結果依掃描順序寫入，暫停時取消尚未完成的請求；解析失敗不會中斷截圖，截圖完成後重試未完成項目。其他特殊狀態或資料不明的個體留待人工核對。解析期間不需要保持手機連線。截圖和解析進度保存在 `.data/`；中斷後維持暫停，可從已完成的檢查點續作。掃描頁顯示已用時間、每隻平均與本階段預計剩餘時間；預估依近期速度計算，未知總數或暫停時不顯示剩餘。總數無法讀取時每 100 隻暫停一次；到達列表終點後可明確確認截圖結束並開始解析。
4. 清倉結果的物種像素圖來自 [PokéAPI Sprites](https://github.com/PokeAPI/sprites)，首次顯示時按需下載並快取於 `.data/sprites/`。可對應的地區及其他形態會優先使用其圖檔；沒有對應圖時使用一般物種參考圖。特殊服裝仍以手機來源截圖為準。
5. 完成解析後在收藏庫核對不確定的個體，查看清倉建議與證據。放生只從「清倉結果」啟動：勾選一隻或多隻後點「放生勾選的 N 隻」。清倉結果會持續顯示進度、逐隻跳過原因和停止操作。暫停後先讓手機返回寶可夢盒列表，再按「繼續」處理原批次中未送出的個體；已送出或結果不明者不自動重送。背景服務先用本機 OCR 確認起點是寶可夢盒，再以勾選的繁中排除條件搜尋候選（預設排除背卡，額外最多兩項）；只有目標 CP 唯一且查詢字串完整時才繼續。接著以固定座標點開個體、選單與放生鍵，並以本機 OCR 排除額外放生警告。放生過程不呼叫 AI，也不在放生後檢查搜尋結果；連續放生同圖鑑編號時保留搜尋結果，換物種或完成批次才返回未篩選的寶可夢列表。iPhone Use 回報點擊完成時記為「已點擊放生（未核對遊戲結果）」；回報不明時整批暫停，不會自動重送。

若要從頭掃描，在掃描進度按「清除未完成掃描並重來」。這會清除所有未完成掃描的截圖、檢查點及該掃描建立的個體，保留已完成掃描和放生歷史。接著在遊戲返回盒子列表，再按「開始掃描」。背景服務仍在處理畫面時，須等目前操作結束才能清除。

iOS 27 的遊戲搜尋欄有時無法向 iPhone Use 提供可讀的文字焦點；繁體中文遊戲使用「背卡」搜尋詞。背景服務若看見系統通知遮住遊戲，會短暫等待並重新觀察；確認遊戲與搜尋鍵盤已開啟後，沿用 iPhone Use 裝置鎖，將圖鑑編號與勾選的排除條件一次送入本機 WDA，並用 OCR 核對實際搜尋文字後點擊確認。若輸入結果不明則暫停，不會自動重送；若無法確認查詢與結果，放生會暫停或跳過該隻。只有完整盒子掃描中圖鑑編號與 CP 唯一，且手機列表 CP 符合目標，才繼續放生。整盒掃描可能耗時且消耗辨識 API 用量，建議先用目前搜尋結果確認版型與用量。

最愛個體照常分析，並在清倉結果標示；若進入你確認的放生批次，執行時會先取消最愛，才繼續放生。鎖定、色違、服裝、傳說／幻之、滿 IV、零 IV、缺少身分資料或額外警告的個體不會進入自動放生批次。招式以繁體中文顯示，也可直接以中文人工修正。進化按鈕若顯示未登錄剪影，且最近一次完整盒子掃描沒有下一階進化型，會列為「可進化」；多分支進化需確認所有下一階都未持有，分支與收藏狀態無法對應時改列待核對。同類進化候選只選 PvP／團體戰潛力、IV 與等級最佳的一隻，並排除放生。能力頁有極巨化或超極巨化徽章時，按同物種保留一隻代表，優先超極巨化，再比較 IV 與 CP；其他個體仍遵守色違、進化、戰鬥名額等既有保留理由。徽章看不清時先待核對，不列入放生。舊手機截圖可在本機執行 `npm run max:recheck` 回填，不需要重新佔用手機。既有人工修正優先；新觀測衝突時需重新核對。不同掃描位置即使數值相同，也不自動合併。

已核對且 IV 合計至少 40/45 的個體，按物種與形態保留 IV 最高的一隻作收藏代表；其餘同物種個體仍依 PvP、團體戰、進化與特殊狀態規則分析。

傳說、幻之與究極異獸不列入「可放生」建議，手機放生執行時也會再次排除；同物種超過收藏代表名額的個體同樣保留。

## 判斷依據與界線

- **PvP**：PvPoke 三大開放聯盟環境排名，與各物種／合法進化分支的 4,096 組 IV 統計乘積排名分開顯示。等級上限 50，CP 上限 1,500／2,500；大師聯盟比較滿等能力。最佳夥伴加一級的 CP 另列，不混入 IV 排名。已超過目標等級的個體不建議進入該聯盟。
- **團體戰**：使用 Game Master **PvE** 招式資料，以等級 35、15 攻 IV 排物種基準；個體再套用自己的攻 IV。固定對方防禦 150、中性傷害、STAB 1.2 與暗影傷害 1.2，快招次數 `ceil(-特殊招式能量 / 快招能量)`，循環傷害除以耗時。同屬性快／特殊招式組合各取最佳，預設物種前十、每屬性保留六隻；可在設定提高到 24 隻，設 12 隻可保留二軍。這是簡化循環 DPS，**不是特定頭目的模擬、存活時間或實戰總傷害排名**。
- **培養**：比較等級 30／35 與 PvP 目標的星塵／糖果／XL 成本。等級需由 CP、HP、IV 唯一確定才顯示總成本；成本明示估算，遊戲活動折扣、特殊物種成本、限定招式與額外進化任務須核對遊戲。成本包含路線進化糖果；換招與開第二招另列，不宣稱已擁有學習器。
- **淨化**：IV 每項加二、上限十五，預估至少等級 25 的 CP；另檢查淨化後的 PvP 潛力與聯盟等級限制。暗影價值不以 IV 星數取代，也不因淨化能滿 IV 就推薦淨化。
- **清倉**：色違、服裝、形態、傳說／幻之、滿 IV、零 IV 各留代表；同物種極巨化或超極巨化個體保留一隻。呱呱泡蛙、呱頭蛙與甲賀忍蛙合併比較，為超級甲賀忍蛙進化線保留一隻已核對且可用的代表；其餘個體顯示保留對象，但仍遵守其他保留與待核對條件。核對完整、未入選戰鬥名額或收藏代表的才列為可放生；未核對個體不擠掉已核對個體的戰鬥名額。只比較本機已掃描且仍持有的個體。
- 第一版以繁體中文直式 iPhone 畫面為主要版型，不分析極巨對戰、限時盃賽或交換最佳化。暱稱、短暫滑動、圖示遮擋及視窗會降低辨識可靠性，必須核對。

## 資料、隱私與檔案

個體、掃描工作、證據、快照與本機連線設定位於忽略版控的 `.data/`。SQLite 使用 WAL；請透過頁面匯出收藏備份，避免服務運行時只複製單一 SQLite 檔案。匯出的 JSON 備份不含 API key 或連線設定。

「設定」頁可清除全部寶可夢資料；須輸入指定確認文字。這會刪除收藏、掃描與放生歷史、截圖和辨識快取，保留連線設定、清倉規則與遊戲資料。手機工作執行期間不能清除。

- iPhone Use 的觀察結果直接擷取畫面；僅將必要裁切截圖送到設定的 Responses API（`store: false`），不經手機相簿。支援版型會裁掉狀態列與評價頁捕獲地點區。其他捲動位置或版型不能保證完全遮蔽，掃描前請避免露出不想傳送的資訊。辨識文字不保存捕獲地點、日期或玩家姓名。
- API key 透過本機設定頁送到後端，存在權限限於目前使用者的 `.data/collection.sqlite`；讀取 API 只回傳是否已設定，備份不包含 key。
- JSON v2 備份包含個體、觀測、來源截圖、掃描與放生歷史、快照及偏好，上限 150 MB；仍接受 v1 備份。還原略過既有 ID，不覆蓋人工修正，也不恢復手機執行授權。API key 與模型快取不在備份中。舊錄影來源的個體與證據仍可查看；不再提供錄影新增或處理入口。
- 前端使用系統字型，無需外部字型服務。此專案僅供私人本機使用，沒有登入或公開部署設定。

資料由設定頁「更新遊戲資料」或 `npm run data:update` 更新。全部來源通過檢查才切換快照，失敗保留舊版本。資料來源：

- [PvPoke](https://github.com/pvpoke/pvpoke) 遊戲資料與排名，MIT；保留授權於 `THIRD_PARTY_NOTICES.md`。
- [PokeMiners Game Master](https://github.com/PokeMiners/game_masters) 及 [繁體中文文字](https://github.com/PokeMiners/pogo_assets)，原始內容權利屬 Pokémon 與遊戲權利人。
- [OpenAI 視覺輸入](https://developers.openai.com/api/docs/guides/images-vision) 與 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。

## 驗證

```sh
npm test
npm run typecheck
npm run build
```

自動測試涵蓋 IV 量測、跨次配對、衝突與人工修正、備份相容、模擬 iPhone Use 斷線／續掃／取消、放生保護與重送限制。辨識測試使用模擬回應，不消耗 API 額度；實際辨識需另用有效 API key 驗證。

## 本機介面

所有寫入需同源與 `x-pogo-local: 1` 標頭。

| 介面 | 用途 |
| --- | --- |
| `GET /api/state`、`GET /api/species` | 收藏、設定與名稱目錄 |
| `GET /api/iphone`、`POST /api/iphone/prepare` | 手機與背景服務狀態、準備連線 |
| `GET/POST /api/scans`、`POST /api/scans/:id/control` | 掃描、進度、暫停／續掃／停止 |
| `POST /api/scans/discard` | 清除未完成掃描以重新開始 |
| `GET/POST /api/transfers`、`POST /api/transfers/:id/exclude` | 放生預覽與排除候選 |
| `POST /api/transfers/execute-one`、`POST /api/transfers/execute-many`、`POST /api/transfers/:id/execute-one`、`POST /api/transfers/:id/stop` | 清倉結果單隻或勾選批次放生、預覽後逐隻執行及停止；舊整批授權入口已停用 |
| `PATCH /api/pokemon/:id`、`POST /api/merge` | 人工核對、鎖定與合併 |
| `POST /api/reevaluate`、`PATCH /api/settings`、`POST /api/data/update` | 重新計算、偏好與遊戲資料 |
| `GET /api/export`、`POST /api/import`、`GET /api/export?format=csv` | 備份、還原及 CSV |
| `GET /api/frames/:scan/:file.jpg` | 本機證據截圖；舊來源路徑仍可讀取 |
